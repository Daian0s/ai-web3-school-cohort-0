## Design Process — 5 Questions Before Writing Code

### 1. Goal
"Give me a smart contract address, tell me basic on-chain info about it — without
changing anything."

### 2. Network
**Sepolia testnet** — not mainnet, no real funds at risk. Needs:
- A free/public RPC URL
- A known contract address on Sepolia to test against

### 3. Tool (starting with just one)
```json
{
  "name": "get_contract_info",
  "description": "Reads basic on-chain info about a smart contract address: whether it has code deployed, and its ETH balance.",
  "parameters": { "address": "string — the contract address to inspect (0x...)" }
}
```
Under the hood, two read calls:
- `eth_getCode(address)` — confirms it's actually a contract, not a plain wallet
- `eth_getBalance(address)` — how much ETH it holds

### 4. The loop (Day 4) applied here
```
User: "Check contract 0xABC..."
OBSERVE → DECIDE (need get_contract_info) → ACT (call the tool)
→ real RPC call → result → LLM explains in plain language
```
A single pass through the loop is enough here — multi-step reasoning comes later
once there are multiple tools to choose between.

### 5. Stack
**Python + web3.py** — simpler syntax for a beginner, and reusable skill for AI tooling
generally (Claude SDK etc.), not a one-off choice. Claude API handles the tool-calling
decision layer.

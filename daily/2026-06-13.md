## Handbook Reading — Web3 Foundations (Completed)

### Chapter 1 — Wallet

**Core idea**: A wallet stores **keys**, not coins. Coins always live on-chain;
the wallet proves ownership.

- **Private key** — huge secret number; whoever holds it controls the funds. Never shared.
- **Public key / Address** — derived one-way from the private key; shared to receive.
- **Seed phrase** (12-24 words) — master backup; all keys derive from it (HD wallet).
- **Signing** — sign a transaction with the private key; the network verifies it with the
  public key **without ever seeing the private key**.

**AI link**: An agent that acts on-chain needs its own wallet to sign → security risk →
constrain with testnet, spend limits, dry-run before broadcast.

### Chapter 2 — Smart Contract

**Core idea**: Code that lives on the blockchain and runs on every node. Once deployed it
is **immutable** — which is exactly why bugs are dangerous (and why auditing exists).

- **Source (Solidity)** → what I read during audits
- **Bytecode** → compiled, runs on the EVM
- **State** → stored data (balances, mappings), permanent on-chain

| Interaction | Cost | Example |
|---|---|---|
| Read (call) | Free | Read a balance |
| Write (transaction) | Gas | Send tokens, change state |

**AI link**: First agent does **reads** (cheap, safe). Writes come later with guardrails.

### Chapter 3 — RPC & Dev Stack

**Core idea**: RPC is the "phone line" to the blockchain — a URL you use to send queries
and get answers. You don't run your own node; you connect to a provider.

- **Analogy**: blockchain = a huge bank with countless branches; you don't go in person,
  you call. The RPC URL is the phone number.
- **Providers**: Alchemy, Infura run the nodes; you rent a URL (free tier to start).
- **Dev stack**: library (`ethers.js` / `web3.py`) + RPC URL + testnet (Sepolia).

**Agent flow**:
```
Claude (decides) → ethers.js (formats) → RPC URL (sends) → Blockchain (responds) → Claude
```

## Handbook Reading — AI Foundations (Completed)

### Chapter 1 — LLM (Large Language Model)

**Core idea**: An LLM is a transformer neural network trained to predict the **next token** given prior context. Chat, code, reasoning — all emergent from this one capability.

**Key concepts:**
- **Token** ≈ 3-4 characters. Costs and limits are measured in tokens, not words.
- **Parameters** = the model's "weights" (Opus 4.7, GPT-4 differ in size and training).
- **Training vs Inference** = trained once (expensive), reused many times (cheap).
- **Stochastic** = different output each run, controlled by `temperature`. Not deterministic.
- **Knowledge cutoff** = knows only up to a fixed date. Does not browse the web by itself.

**Web3 link**: An LLM cannot execute on-chain transactions alone. It needs **tools/agents** (RPC, signers). That bridge is the AI→blockchain integration layer.

### Chapter 2 — Prompt

**Core idea**: The prompt is the **input**. Everything the model has to work with — instructions, examples, data — must be in it.

**Anatomy of a good prompt (4 parts):**
1. **Role/Persona** — "You are a Solidity security auditor."
2. **Task** — Clear instruction.
3. **Context/Data** — The material (code, docs, examples).
4. **Output format** — JSON, markdown, list, etc.

**Techniques:**
- **Zero-shot** — Plain question, no examples.
- **Few-shot** — 2-3 input→output examples. Big accuracy boost.
- **Chain-of-Thought (CoT)** — "Think step by step" for reasoning.
- **Structured output** — Request JSON schema for programmatic parsing.

**Common mistakes:** vague prompts, conflicting instructions, missing context.

### Chapter 3 — Context

**Core idea**: The **context window** is the total tokens the model can "see" at once (input + output). Opus 4.7 = 200K tokens.

**Important distinction**: Context is **not memory**. It's the model's "desk" — the papers laid out in front of it right now. The model does not remember; each turn the full history is re-read.

**Strategies:**

| Strategy | When | Example |
|---|---|---|
| **Truncation** | Long history | Keep last N messages |
| **Summarization** | Long conversations | Compress old context into a summary |
| **RAG (Retrieval)** | Many docs | Embed → search → inject only relevant chunks |
| **Prompt caching** | Repeated system prompt | Cache hit ≈ 90% cheaper |

**RAG in one paragraph**: Split docs into chunks → embed each chunk into a vector → at query time, retrieve top-K relevant chunks → inject them into the prompt.

**Web3 link**: For an agent that "knows" 50 smart contracts, don't dump them all into context — use RAG with embeddings.
